# 模型多模态能力预检

在执行 Step 0 之前先运行本预检。目标是确认当前模型和会话真的能理解用户提供的视觉素材，避免用户安装 Skill 后得到基于文件名、视频标题或元数据编造的分析。

## 最低能力要求

| 用户素材 | 可以继续的最低条件 |
|---|---|
| 图片 | 当前模型/会话具备图像输入能力，且能够实际读取用户提供的图片 |
| 视频 | 路径 A：具备原生视频理解能力；或路径 B：能够在本地抽帧，且当前模型/会话具备图像输入能力 |
| 图片与视频混合 | 图片满足图像输入要求；视频满足路径 A 或路径 B |

只支持文字、文件名解析、视频时长读取或普通 OCR，不等于具备本 Skill 所需的视觉理解能力。

## 检测顺序

1. 查看宿主或当前会话明确提供的能力声明，例如支持的输入模态、附件类型和可用视觉工具。
2. 若宿主没有明确声明，使用用户已提供的非敏感素材做最小实际探测：图片尝试读取一张；视频尝试直接读取，失败后再检查能否本地抽取一帧并把该帧输入模型。
3. 不要仅凭模型名称、模型系列、供应商宣传或以往会话经验判断当前会话一定支持图片或视频。
4. 探测成功只代表当前会话的这条输入路径可用。用户切换模型、供应商或会话后必须重新检查。
5. 无法获得明确声明且最小实际探测也不能完成时，将结果记为“能力未知”，按不通过处理。

探测只用于确认能否读取视觉内容，不要在预检阶段输出车牌、违法结论或其他敏感内容。

## 通过后的执行路径

### 图片输入通过

确认模型能读取图片内容后再进入 Step 0。后续仍需按证据和车牌硬闸门判断，不能把“能看图”写成“识别准确”。

### 原生视频理解通过

确认模型能读取连续视频画面及时间顺序后，可以直接扫描完整视频。仍要记录候选事件的时间点，并为关键判断保留原始帧。

### 仅能通过本地抽帧处理视频

先保留原视频，再使用宿主已有的确定性媒体工具在本地抽帧，并把带时间戳的帧图片输入模型：

1. 先低频扫描完整视频，建立候选时间段。
2. 再对候选时间段密集抽帧，检查信号变化、车辆轨迹、标线和车牌。
3. 保留帧的时间顺序和原始路径，不覆盖原视频。
4. 如果违法判断依赖抽帧间隔中没有记录到的动作，标记“证据不足”，不得用相邻帧猜测中间过程。

本地抽帧只是视频输入的降级路径，不代表模型具备原生视频理解能力。

## 不通过时的提醒与停止

普通 Skill 无法保证弹出操作系统级对话框，因此必须在聊天中输出置顶、醒目的阻断提醒；如果宿主提供原生弹窗或通知能力，可以同时使用。

图片能力缺失或能力未知时，输出：

> ⚠️ 当前模型/会话未检测到可用的图像输入能力。“行车正义”必须读取图片内容才能识别违法行为和车牌，当前无法继续。请切换到支持图片理解的多模态模型后重新运行本 Skill。

视频既不能原生理解、也不能通过本地抽帧转成图片时，输出：

> ⚠️ 当前模型/会话无法读取视频，也没有可用的本地抽帧＋图像理解路径。“行车正义”当前无法分析这段视频。请切换到支持视频理解的多模态模型，或先把视频转换为连续关键帧图片后重新运行。

提醒后立即停止，不进入 Step 0—9，不生成候选违法、车牌、法律定性、表单内容或台账记录。不要用“我大概能看”“可以根据标题判断”等措辞绕过能力闸门。
