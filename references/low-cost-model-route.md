# 低成本模型链路（可选）

该链路用于博主授权素材试水和候选扫描，不取代 Step 2—9 的人工确认、法律核验和官方提交边界。

## 分工

1. 在本地使用 `ffmpeg` 以 2 fps 扫描完整素材，保留时间顺序和时间戳。
2. 使用火山方舟 Doubao Seed 2.0 Lite 列出候选事件；本阶段禁止输出车牌字符。
3. 对每个候选窗口按 4 fps 密集抽取原始帧，再由视觉模型复核行为、车牌清晰度和车辆轨迹。
4. 对初次复核给出的车牌帧再做一次独立重读：不把候选号码告诉复核请求，视频至少两帧（单张图片则为该图）的完整读数必须逐字一致。
5. 车牌只有在结构化结果同时满足“前牌或后牌一面全部清晰、轨迹连续、车牌帧和行为帧引用有效、独立重读一致”时，才进入本地车牌注册表；自由文本中的车牌一律丢弃。
6. 使用 `deepseek-v4-flash` 去重和规范化文字 JSON；Flash 输出无法解析或明确标记冲突时，再使用 `deepseek-v4-pro` 复核。DeepSeek 只接触车牌引用，不接触实际车牌字符。
7. 使用本地脚本生成单个 `analysis.xlsx`，将关键帧嵌入单元格。

## 运行

先安装 `ffmpeg` 和 `requirements.txt` 中的 Python 依赖，然后在当前终端临时设置 API Key：

```bash
export ARK_API_KEY="..."
export DEEPSEEK_API_KEY="..."
python scripts/run_low_cost_pipeline.py \
  --input /absolute/path/to/clip.mp4 \
  --output /absolute/path/to/analysis.xlsx \
  --city "义乌" \
  --source-note "博主已授权测试"
```

API Key 只能放在当前终端环境变量或私密密钥管理器中，不得写入 Skill、结果表、日志或 Git 文件。

默认模型可通过参数或环境变量替换；实际运行前必须在火山方舟控制台确认当前账号可用的 Seed 2.0 Lite 模型 ID。

## 车牌边界

试跑 Excel 允许写入通过确定性闸门与独立重读的模型车牌判断，并标记“待人工复核”。它不能直接进入正式举报表单。用户决定继续举报时，仍须按 `references/plate-verification.md` 查看原始车牌帧、行为帧和连续轨迹并亲自确认。

`--normalized-json` 可用于无 API Key 的离线测试。它只验证结构化车牌闸门和 Excel 链路，不证明真实模型已成功识别视频。

## 限制

- 完整扫描与候选窗口密集复核都仍可能漏掉抽帧间隔中的瞬时动作；模型返回“未发现”不等于原视频没有违法。
- 模型返回“未发现”不等于原视频一定没有违法。
- 该链路不进行官方法条原文核验、渠道检索或表单提交；需要继续举报时回到 SKILL.md 的完整流程。
