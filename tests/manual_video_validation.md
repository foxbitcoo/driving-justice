# 公开视频人工前向验证记录

本文件记录 `driving-justice` 工作流针对公开交通视频的人工前向测试结果。它不是自动化视觉模型的准确率基准，也不代表任何举报平台已经受理。

测试约束：

- 视频标题、作者描述只作为“来源标签”，不得直接当成识别结果。
- 本轮由具备图像输入能力的多模态模型配合本地抽帧完成，只验证该路径可用，不代表纯文本模型或其他宿主安装 Skill 后也能分析视觉素材。
- 识别结论必须由画面本身支持；画面存在方向、信号控制对象、标线类型或剪辑歧义时，不下确定结论。
- 通过违法候选识别不等于通过车牌闸门。前牌或后牌至少一面必须全部清晰，而且车牌帧到违法瞬间的车辆轨迹必须连续；任一项不满足就在 Step 4 停止。
- 公开视频只在本机 `/tmp` 或被 `.gitignore` 排除的 `local-tests/` 中用于测试。Git 跟踪范围仅保存来源链接、时间窗和结论，不保存或重新分发视频、关键帧、车牌值。
- 因测试素材不是用户准备实际举报的原始证据，本轮不执行 Step 6—9，不查询真实举报渠道、不预填官方表单、不写入本地举报台账。

## 本轮验证结论

1. 工作流把“候选违法识别”和“车牌可用于举报”分成两个独立结论。2026-07-30 起车牌规则改为“前牌或后牌至少一面清晰＋轨迹连续＋用户确认”；旧规则下仅因缺少另一面车牌而停止的结论全部作废，必须按新规则重测。
2. 两条来源标题明确写有违法的视频，没有被标题直接带成肯定结论，验证了“只写画面能证明的事实”这一边界。
3. 本轮仍不是完整 Step 0—9 端到端验收：未完成真实用户目标选择、可见一面车牌的逐字符确认、官方法条原文现场核验、真实举报渠道预填、用户提交和平台受理。
4. 是否推送 GitHub 应由代码、文档、隐私边界和仓库检查决定，不应由某条测试视频能否通过车牌闸门决定。
